# Как делаем шаг плана

Каждый шаг: своя ветка от `dev`, после шага стоп. Ветки и коммиты делает Павел, `git push` тоже он. Ты ветки не создаёшь (даже `checkout -b`), работаешь на `dev` в рабочей копии.

1. Прочитай `HANDOFF.md` («Следующий шаг») и нужный шаг в `CLAUDE.md` (grep «Шаг N.»). CLAUDE.md и DESIGN.md большие: целиком не читай. Если HANDOFF расходится с `git log` и `git status`, верь git и поправь HANDOFF.
2. Найди код grep'ом, правь. Мёртвый код и тексты про убранное (README, комментарии, `decor.ts`) вычищай.
3. Проверка: `npm run typecheck`, `npx tsc --noEmit --noUnusedLocals`, `npm run build`. Для шагов с балансом сначала симуляция (скрипта нет, пишется по CLAUDE.md).
4. Картинка: `bash .claude/skills/next-step/hookbuild.sh <scratchpad> .` — сборка с хуком `window.__g` (сцена) в `<scratchpad>/dist`, исходник возвращается сам. Скопируй `shot.mjs` в scratchpad, перепиши сценарий под шаг (сейчас там проверки Дилера шага 42: `check`, очередь `window.__q` для `Math.random`), запусти `node shot.mjs <scratchpad>`, посмотри PNG. Порт 5173 не трогать.
   - `Math.random` подменяй очередью (`window.__q`), а не константой: игра берёт число в следующем кадре, константа ломает тексты Phaser.
   - Клик мышью: точка страницы = левый край холста + (x − `cam.scrollX`) × `cam.zoom` × (ширина холста / 1920), так же по y. Не `worldView`.
   - Клавиши: имена Phaser (`keydown-PLUS` для «=», код 187), а не названия символов.
   - Симуляции частей — `drum-chips-sim.mjs`, `dealer-sim.mjs` (образцы). Оптимум «по среднему» может уйти в бесконечность — тогда мерь политикой человека (шанс ≥ 70%).
5. Обнови `CLAUDE.md` (галочка + «Сделано» + «Коммит: ...», строка «Сейчас» вверху, разделы «Что уже есть в игре», «Обратная связь», «Как устроить код», если шаг их задел), `HANDOFF.md` (план, состояние, следующий шаг), CHANGELOG не трогай до конца шагов 36-45.
6. Ответ Павлу: что сделано, что проверено, имя ветки `feature/...` или `fix/...` и сообщение коммита по-английски (формат `feat: ...` / `fix: ...`). Стоп.
